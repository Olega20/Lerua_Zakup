# Lerua Zakup — дизайн первого этапа интеграции с МойСклад

- Дата: 2026-11-19
- Статус: подготовлено для проверки и утверждения пользователем
- Основа: `docs/requirements/AGREED_REQUIREMENTS.md`
- API: официальный МойСклад JSON API 1.2
- Архитектура: существующая модульная feature-first архитектура Flutter

## 1. Цель этапа

Подключить приложение к МойСклад безопасным способом, подтвердить действительность сохранённого Access Token, показывать реальное состояние связи и создать первую рабочую версию Журнала склада для диагностических событий.

Главный экран должен открываться сразу и оставаться доступным при отсутствии сети, недоступности API, отсутствии/ошибке токена. На этом этапе приложение не загружает товары, склады или остатки и не создаёт/изменяет/удаляет документы.

## 2. Объём работ

Входит:
1. API Manager — единая точка HTTP-взаимодействия с МойСклад.
2. Проверка токена безопасным GET-запросом к `/api/remap/1.2/context/employee/`.
3. Проверка интернет-состояния через уже существующий Android Connectivity EventChannel.
4. Три состояния индикатора: красный / жёлтый / зелёный.
5. Автоматическая проверка при запуске, после сохранения токена, при восстановлении интернета и при возвращении приложения на передний план после длительной паузы.
6. Защита от параллельных запросов, тайм-аут 10 секунд и корректная отмена/игнорирование устаревших результатов.
7. Реальный экран Журнала склада с локально сохранёнными диагностическими событиями.
8. Snackbar с короткой причиной ошибки при ручном сохранении токена/проверке, если это предусмотрено существующим поведением; подробности — в журнале.
9. Unit/widget tests и локальная сборка APK.

Не входит:
- Получение списков сотрудников, организаций, складов, товаров и остатков.
- Создание, изменение или удаление любых сущностей и документов.
- Очередь бизнес-операций, синхронизация, фоновые Android Services и постоянное уведомление.
- Автоматическое получение/обновление токена, логин/пароль, OAuth.
- Отображение сырых HTTP-ответов или токена пользователю.

## 3. Архитектура

### API Manager

Предлагаемая зона:
`lib/features/connectivity/data/moysklad_api_client.dart` и `moysklad_api_manager.dart` (точное разделение по результату реализации).

Обязанности:
- Единственная точка для HTTP-запросов к `https://api.moysklad.ru`.
- Получает токен из SecureTokenStore только непосредственно перед запросом.
- Добавляет заголовки `Authorization: Bearer <Access-Token>`, `Accept: application/json`, `Accept-Encoding: gzip`.
- Не помещает токен в URL, исключения, логи, Snackbar или диагностические события.
- Выполняет только разрешённые на этом этапе GET-запросы.
- Возвращает типизированный результат проверки, не отдаёт UI сырой ответ.
- Обеспечивает единственный активный запрос проверки; повторный триггер объединяется/откладывается, а не создаёт параллельный запрос.
- Тайм-аут 10 секунд. При потере сети активная проверка становится неактуальной; поздний ответ не может вернуть зелёный индикатор после перехода в offline.
- Использовать встроенный Dart `dart:io HttpClient` (или эквивалент после проверки) без новой HTTP-зависимости, если это обеспечивает gzip и тестируемую подмену транспорта. Если потребуется пакет, его совместимость и необходимость отдельно обосновать.

### Проверка авторизации

Запрос:
`GET https://api.moysklad.ru/api/remap/1.2/context/employee/`

- HTTP 200 и корректный JSON-объект — проверка успешна.
- HTTP 401 — токен не принят/не действителен.
- HTTP 403 — авторизация распознана, но нет права на запрошенный ресурс; связь с API не считать подтверждённой зелёным статусом.
- HTTP 429 — лимит API; учитывать заголовки задержки/повтора, не запускать частые повторы.
- HTTP 5xx, некорректный ответ, DNS/TLS/socket error или timeout — проверка неуспешна.
- Любая ошибка при наличии интернета оставляет индикатор жёлтым.
- Отсутствие токена: запрос не отправлять, индикатор жёлтый.

Не делать вывод о полном доступе пользователя к будущим операциям на основании успешного context/employee: это только проверка валидности токена и доступности API.

### Интернет и состояния индикатора

Существующий Android EventChannel уже сообщает наличие сети с NET_CAPABILITY_INTERNET и NET_CAPABILITY_VALIDATED.

- Красный: Android сообщает, что подтверждённого интернет-соединения нет.
- Жёлтый: интернет есть, но успешная проверка API ещё не получена, токен отсутствует или API ответил ошибкой.
- Зелёный: последняя актуальная проверка завершилась HTTP 200 с корректным JSON.
- При восстановлении сети сначала жёлтый, затем выполняется новая проверка.
- При потере сети красный устанавливается немедленно; результат ранее запущенного запроса игнорируется.
- Визуальный вид индикатора остаётся полоской 4 px, без текста/значков.

## 4. Когда выполнять проверку

Согласованные триггеры:
1. Холодный запуск приложения — главный экран показывается немедленно, проверка запускается асинхронно после готовности настроек и первого состояния сети.
2. Успешное сохранение нового токена — проверить сразу.
3. Восстановление подтверждённого интернета — проверить сразу после перехода в жёлтый.
4. Возврат приложения в foreground — проверить, если последняя проверка старше 5 минут или состояние сети/токена изменилось.

Предлагаемая периодичность:
- Пока приложение находится в foreground и интернет доступен, повторять проверку не чаще одного раза в 5 минут.
- В background периодический опрос не выполнять; Android Service на этом этапе не создавать.
- Любые повторные проверки ограничиваются rate limit МойСклад; после 429 соблюдать серверную задержку, если она передана.
- Одновременно допускается только один HTTP-запрос проверки.

Интервал 5 минут — техническое предложение для утверждения, а не уже согласованное пользовательское требование.

## 5. Журнал склада

Экран открывается из настроек вместо текущей заглушки.

В первой версии журнал содержит только диагностические события интеграции:
- запуск проверки;
- проверка успешна;
- токен отсутствует;
- отказ авторизации;
- запрет доступа;
- лимит API;
- тайм-аут;
- сетевая ошибка/API недоступен;
- потеря и восстановление интернета;
- токен сохранён/удалён (без значения токена).

Запись события:
- дата и время устройства;
- уровень (информация / предупреждение / ошибка);
- короткий тип события;
- безопасное описание;
- HTTP status code и безопасный API error code, если они доступны.

Запрещено сохранять:
- Access Token и его фрагменты;
- заголовки Authorization;
- полный сырой ответ API;
- персональные данные сотрудника из context/employee;
- полные URL с чувствительными параметрами.

Предлагаемая реализация хранения — локальная SQLite база, отдельный репозиторий журнала. Предлагаемый предел — 500 последних записей; при превышении самые старые удаляются. Записи сохраняются после перезапуска и не отправляются никуда. Пользователь сможет открыть запись и скопировать безопасные диагностические сведения; очистка журнала будет подтверждаться. Лимит 500 — техническое предложение.

## 6. Ошибки и пользовательские сообщения

- На главном экране не показывать модальные окна и не задерживать работу из-за проверки.
- При сохранении токена оставить согласованное маскированное отображение.
- При неуспехе проверки после сохранения токена показывать краткий Snackbar без токена и без сырого ответа.
- Подробное, но очищенное от секретов описание записывать в Журнал склада.
- Не показывать повторяющиеся Snackbar при автоматических периодических проверках; автоматические ошибки доступны в журнале, индикатор остаётся жёлтым.
- Отсутствие интернета не считается ошибкой API и не должно вызывать запрос.

## 7. Безопасность и приватность

- Токен читается только из Android secure storage.
- Передача только по HTTPS.
- Запрет redirect-follow с Authorization на другой host; не пересылать токен на иной домен.
- Не логировать request headers, request body, response body или полный исключительный текст, если он может содержать секрет.
- Тайм-аут и закрытие клиента должны освобождать сетевые ресурсы.
- Не добавлять токен в Crash/analytics/clipboard.
- Все ответы API считать недоверенными данными и проверять тип/формат.

## 8. Проверки и критерии приёмки

Unit tests:
- HTTP 200 -> green; 401/403/429/5xx/timeout/socket failure -> yellow.
- Bearer header и gzip/Accept headers передаются корректно; токен не появляется в логах/ошибках.
- При отсутствии токена HTTP запрос не выполняется.
- Параллельные триггеры не создают параллельных запросов.
- Тайм-аут завершает попытку за 10 секунд.
- Поздний ответ после потери сети не возвращает green.
- Reconnect и token-saved запускают проверку.
- Foreground resume применяет условие 5 минут.
- Rate limit не провоцирует частые повторы.
- Журнал сохраняет события, сортирует новые сверху, ограничивает объём и очищает данные по подтверждённому действию.

Widget tests:
- Индикатор корректно показывает все три цвета.
- Главный экран отображается до завершения/при зависшей проверке.
- Экран журнала показывает пустое состояние, события и безопасные детали.
- Snackbar автоматических периодических ошибок не спамит пользователя.

Manual Android tests:
- запуск без токена и без интернета;
- запуск с валидным токеном;
- запуск с неверным токеном;
- отключение/восстановление Wi-Fi и мобильной сети;
- сворачивание и возврат;
- удаление токена;
- проверка журнала после перезапуска.

## 10. Вопросы для утверждения перед реализацией

1. Подтвердить периодическую проверку каждые 5 минут только пока приложение открыто (foreground); в фоне не опрашивать.
2. Подтвердить хранение 500 последних диагностических записей в локальном журнале.

4. Подтвердить, что автоматические фоновые ошибки не показывают повторяющиеся Snackbar; подробности доступны в журнале, индикатор становится жёлтым.
