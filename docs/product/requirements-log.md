# Product requirements log

This file stores decisions confirmed by the product owner. Each questionnaire batch is appended with the date, original question, answer, and resulting implementation decision.

## Confirmed decisions before questionnaire

- Show every inventory document available in MoySklad in the inventory section.
- Fetch remote MoySklad inventories and their positions on demand; do not permanently store their remote data in the app's local database.
- Allow editing inventory records/positions in MoySklad.
- Record local inventory draft creation/deletion, submission, remote edits, and failures in the warehouse journal as a chronological event history.
- Keep unsent local drafts on-device for offline continuation.

## Раунд 1 — закупка, заказ и перемещение

Дата фиксации: 2026-11-26

1. **Состав списка товаров:** A — показывать все актуальные товары с соответствующим флажком независимо от остатков.
2. **Несколько складов:** A — полностью проходить товары для первого склада, затем переходить к следующему.
3. **Места хранения:** C — при создании выбирать склады; места хранения не ограничивать.
4. **Отображение остатка:** A — показывать общий остаток по выбранному складу.
5. **Количество закупки/заказа:** A — вводить дополнительное количество к приобретению; текущий остаток показывать для справки.
6. **Товар без поставщика:** B — создавать отдельную запись «Без поставщика».
7. **Товар с несколькими флажками:** A — создавать независимые операции каждого отмеченного типа.
8. **Группировка мест хранения:** A — одна запись поставщика на склад, места хранения перечислять внутри неё.
9. **Незавершённое внесение:** A — сохранять черновик и позволять продолжить позже.
10. **Нумерация:** A — автоматический сквозной номер отдельно для каждого типа операций.

### Следствия для реализации

- Отбор товаров производится по флажку типа операции, а не по наличию остатка.
- Сессия внесения проходит склад за складом; внутри склада учитываются все его места хранения без отдельного фильтра.
- Количество вводится как дополнительное к закупке/заказу, не как целевой остаток.
- Отсутствующий поставщик не блокирует внесение: его позиции группируются в отдельную запись «Без поставщика».
- Если товар отмечен несколькими типами, соответствующие типы обрабатываются независимо.
- Группировка календарных документов — по типу операции, складу и поставщику; места хранения не создают отдельные документы.
- Незавершённая сессия должна быть восстанавливаемым локальным черновиком.
- Номер генерируется независимо в пределах каждого типа операций.

## Раунд 2 — закупка, заказ и перемещение

Дата фиксации: 2026-11-26

1. **Перемещение между складами:** A — выбрать склад-источник и склад-получатель; количество списывается с первого и приходуется на второй.
2. **Отбор товаров для перемещения:** B — включать товары с флажком «Перемещение» и разрешить вручную добавлять другие товары.
3. **Дата перемещения в календаре:** A — текущая дата.
4. **Группировка календарных записей:** A — отдельная запись на каждый склад и поставщика в рамках типа операции.
5. **Список старых операций:** A — показывать дату, номер, склад и поставщика.
6. **Действия с созданной записью:** B — просмотр и удаление всей записи; редактирование содержимого пока не требуется.
7. **Создание календарных записей:** A — сразу после нажатия «Завершить».
8. **Склад без введённых количеств:** A — не создавать для него запись.
9. **Порядок товаров:** пользовательский вариант — сортировать сначала по порядку мест хранения (в том порядке, в котором они расположены в системе), затем внутри каждого места хранения по алфавиту.
10. **Снимок данных товара:** A — сохранять сведения о товаре на момент создания операции.

### Следствия для реализации

- Перемещение должно иметь два склада: источник и получатель; после подтверждённого завершения требуется отразить расход на источнике и приход на получателе. Нужны проверки, исключающие совпадение складов и отрицательный остаток/недостаточное количество на источнике (точные правила ещё уточнить).
- В перемещение автоматически попадают товары с соответствующим флажком, но пользователь может вручную добавить иные товары.
- Дата записи перемещения — дата завершения, текущий день.
- Группировка календаря остаётся раздельной по типу операции, складу и поставщику.
- В списке операций показываются только дата, номер, склад и поставщик; количество позиций и сумма не обязательны.
- Существующую запись можно открыть для просмотра или удалить целиком; частичное редактирование не входит в текущий объём.
- Записи календаря создаются синхронно с командой завершения пользовательского сценария, после подтверждения действия; пустые складские группы пропускаются.
- Сортировка товаров учитывает порядок мест хранения, заданный в МойСклад, а внутри места — алфавитное имя товара.
- В строках операции необходимо хранить неизменяемый снимок существенных атрибутов товара на момент создания, чтобы последующие изменения справочника не переписывали историю.
