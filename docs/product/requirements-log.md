- При ошибке финального сохранения данные остаются в черновике; повторное завершение должно быть безопасным и не создавать дубликаты уже сохранённых календарных записей.

4. **Точность количества:** C — допустимая точность определяется единицей измерения товара.
5. **Отрицательное количество и остаток:** пользовательское уточнение — отрицательное количество закупки вводить нельзя; при этом сам складской остаток может оставаться отрицательным. Это не означает автоматического запрета отображать или учитывать отрицательный текущий остаток.
6. **Сохранение черновика:** B — сохранять изменения при переходе к следующему товару.
7. **Количество черновиков:** пользовательский вариант — разрешить несколько черновиков одного типа операции, с возможностью удалять черновики.

10. **Срок жизни черновика:** пользовательский вариант — автоматически удалять черновики через неделю; также разрешить ручное удаление.

### Следствия для реализации

- В календаре операции должны визуально группировать строки по поставщикам: заголовок поставщика, под ним товары; далее следующий поставщик. Сохраняется согласованная ранее группировка по типу операции и складу.
- Внутри подробного представления показывать товар, введённое количество, единицу измерения и текущий остаток.
- Формировать номер с префиксом типа, годом и последовательностью, например З-2026-0001; ранее согласованная независимая нумерация по типам сохраняется.
- Ввод количества должен учитывать точность, допустимую для единицы измерения; отрицательное количество закупки/заказа не разрешать. Отрицательный складской остаток сам по себе допустим и должен корректно отображаться.
- Сохранять черновик при переходе к следующему товару, а не требовать отдельного нажатия сохранения после каждого изменения.
- Разрешить несколько черновиков каждого типа и обеспечить отдельное ручное удаление черновика.
- Изменение флажков товара в справочнике после включения товара в черновик не должно автоматически удалять этот товар из черновика.
- Для автоматического выбора места хранения использовать единственное место хранения товара в выбранном складе; если его нет, требуется определить поведение в следующем раунде.
- Добавить срок жизни черновика: автоматическое удаление через 7 дней и ручное удаление. Для корректной реализации необходимо определить, от какого момента считать неделю, и предупреждать ли пользователя перед автоматическим удалением.

### Следствия для реализации

- Экран создания позволяет выбрать несколько складов за один раз. При этом введённые количества независимы для каждого склада; нельзя переносить или автоматически суммировать количество между складами.
- Сохраняется согласованный ранее принцип обработки складов последовательно: выбранные склады обрабатываются один за другим в рамках единой сессии, а группы календарных записей формируются по каждому складу отдельно.
- Для закупки использовать текущую дату, для заказа — следующий календарный день. Ранее установленная дата перемещения (сегодня) не меняется.
- Новые поля количества изначально пустые. Пустое поле и пропуск не равны нулю; пропущенные строки не включаются в завершённую операцию.
- При возвращении к пропущенному товару не подставлять ноль или предыдущее значение автоматически; пользователь должен явно ввести количество.
- Снимки названия, единицы измерения, остатка и других согласованных исторических данных формировать на этапе завершения, а не при создании черновика. Это уточняет прежнее общее решение о снимке при создании операции: точкой фиксации является Finish.
- Поставщика для группировки и сохранения в завершённой операции получать из актуального справочника на момент завершения. Это означает, что смена поставщика во время существования черновика влияет на итоговую группировку.
- Перед ручным удалением черновика показывать подтверждение; автоматическое удаление просроченных черновиков при запуске приложения остаётся без предупреждения согласно раунду 5.
- **Отменено уточнением пользователя после раунда 6:** из календаря ничего не открывается; товары показываются непосредственно в календаре внутри сворачиваемых групп «Поставщик на склад». См. уточнение после раунда 6.
- Основной режим ввода — один товар за раз с кнопкой «Далее». Возможность отдельного табличного режима не подтверждена и не должна добавляться без нового решения.
