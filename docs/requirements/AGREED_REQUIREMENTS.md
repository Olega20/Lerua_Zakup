- **Согласовано:** новый приватный GitHub-репозиторий — `Olega20/Lerua_Zakup`, основная ветка — `main`.
- **Согласовано:** package name нового приложения должен отличаться от старого.
- **Согласовано:** приложение запускается сразу на главном экране, без приветствия и мастера первоначальной настройки.
- **Согласовано:** интерфейс первой версии работает только в вертикальной ориентации.
- **Согласовано:** требования фиксируются в этом документе в GitHub; после каждого ответа/решения пользователя документ обновляется отдельным коммитом. Нерешённые вопросы отмечаются как открытые, предложения разработчика не выдаются за решения пользователя.

## 4. Календарь

### Назначение и данные
- **На будущее:** календарь показывает операции из «Журнала склада» и служит инструментом приёмки и отслеживания состояния действий.
- **На будущее:** в календаре будут отображаться закупки, заказы, перемещения и прочие действия.
- **На будущее:** записи календаря создаются автоматически при создании операций; вручную события календаря не создаются.
- **На будущее:** при изменении плановой даты операция автоматически переносится на новую дату.
- **На будущее:** при отмене/удалении операция остаётся в истории: запись перемещается в конец списка соответствующего дня и помечается «Удалено».
- **На будущее:** при восстановлении операция ставится на текущую дату и время восстановления.
- **Согласовано:** на текущем этапе не показывать тип, номер, название, статус и цветовую категоризацию операций; не показывать индикаторы дней с операциями.

### Вид и навигация
- **Согласовано:** при каждом запуске приложения календарь открывается на текущей дате.
- **Согласовано:** на главном экране отображается недельная полоса с понедельника по воскресенье.
- **Согласовано:** недельная полоса статична: без свайпа и переключения недели. Можно выбрать день или раскрыть полный календарь.
- **Согласовано:** полный календарь открывается на отдельном полноэкранном экране.
- **Согласовано:** месяцы в полном календаре переключаются горизонтальным свайпом; стрелки переключения не нужны.
- **Согласовано:** неделя в полном календаре начинается с понедельника.
- **Согласовано:** при выборе даты полный календарь остаётся раскрытым, под ним отображается список операций выбранной даты; при смене даты список обновляется.
- **Согласовано:** если записей нет, показывается текст «Нет операций за этот день».
- **Согласовано:** при возврате из полного календаря на главное меню всегда выбирается текущая дата, а не ранее выбранная дата.
- **Согласовано:** возврат выполняется системной кнопкой Android «Назад» или системным жестом назад.
- **Открыто:** точное содержимое и оформление пустого списка на первом офлайн-этапе, помимо согласованного текста для даты без операций.

## 5. Индикатор связи и интеграция с МойСклад

### Внешний вид и состояния
- **Согласовано:** индикатор — горизонтальная полоска на всю ширину экрана, высотой 4 px, без текста и значков.
- **Согласовано:** зелёный — API МойСклад успешно ответил.
- **Согласовано:** жёлтый — интернет есть, но API не подтвердил успешную связь (например, токен отсутствует, тайм-аут, ошибка API, отказ авторизации, лимит запросов).
- **Согласовано:** красный — интернет полностью отсутствует, независимо от типа подключения (Wi-Fi или мобильная сеть).
- **Согласовано:** состояние интернет-подключения отслеживается системным способом. Потеря интернета должна сразу переводить индикатор в красный; восстановление интернета — в жёлтый до успешного ответа API.
- **Согласовано:** ошибка API, включая авторизацию и лимиты, отображается жёлтым состоянием; подробная обработка ошибки в будущем относится к Журналу склада.

### Проверки и фон
- **Согласовано:** проверка связи планируется при запуске и периодически.
- **Согласовано:** интервал/тайм-аут проверки — 10 секунд; одновременно выполняется не более одной проверки. Если ответ не пришёл за 10 секунд, текущая проверка отменяется и запускается следующая. Запросы не должны накапливаться или выполняться параллельно.
- **Согласовано:** проверка не должна блокировать интерфейс; сетевые операции асинхронные.
- **Согласовано:** при потере интернета индикатор становится красным сразу; после восстановления — жёлтым и запускается новая проверка.
- **На будущее:** фоновые проверки и обработка запросов продолжаются при сворачивании приложения/переходе в другое приложение.
- **На будущее:** пользователь согласен на Foreground Service с постоянным уведомлением, если он потребуется для надёжной фоновой работы.
- **Согласовано:** в первой версии интеграции реализуется только проверка связи; прочие запросы API добавляются позже.
- **Согласовано:** пока собирается базовая офлайн-версия, не запускать ненужные API-запросы и не усложнять приложение преждевременной сетевой архитектурой.

### Менеджер API
- **На будущее:** отдельный Менеджер API — единая точка всех действий, связанных с API МойСклад.
- **На будущее:** задания API ему выдаёт Журнал склада; ответы API через Менеджер API возвращаются в Журнал склада.
- **На будущее:** отдельные записи/разделы не должны выполнять самостоятельные запросы к API; Менеджер организует запросы централизованно. Детали очередей и пакетной обработки будут согласованы отдельно.
- **Согласовано:** исключение из маршрута через Журнал склада — индикатор связи: он обращается непосредственно к Менеджеру API; Менеджер проверяет связь с МойСклад и отдаёт статус индикатору напрямую.
- **Открыто:** точный API endpoint/метод проверки связи и детали сетевой реализации.


- **Согласовано (2026-11-19):** пока проверка API ещё не реализована, индикатор показывает жёлтый цвет при наличии интернета и красный при его отсутствии. Зелёный цвет появится только после реализации проверки и подтверждённого успешного ответа API.

## 6. Журнал склада

- **Согласовано:** доступ к Журналу склада будет через настройки; отдельного пункта в главном меню нет.
- **Согласовано:** в первой офлайн-версии — только пункт-заглушка; реальный экран и механизм журнала пока не реализуются.
- **На будущее:** Журнал склада — центральный механизм обработки и распределения данных, а не просто экран.
- **На будущее:** все операции приложения сначала попадают в Журнал склада; он обрабатывает данные и распределяет их по разделам.
- **На будущее:** остальные разделы получают данные из Журнала склада.
- **На будущее:** ошибки автоматически попадают в раздел «Ошибки» Журнала склада; их можно копировать непосредственно из журнала.
- **На будущее:** сообщения внизу экрана не заменяют запись ошибки в Журнале склада.

## 7. Настройки

На первом этапе предусмотрены только три пункта:
1. Тема оформления.
2. API-токен.
3. Журнал склада (пока заглушка).

### Тема
- **Согласовано:** доступны три режима: «Светлая», «Тёмная», «Системная».
- **Согласовано:** первый запуск — со светлой темой.
- **Согласовано:** переключение темы применяется сразу, без перезапуска.
- **Согласовано:** выбранная тема сохраняется после закрытия приложения.
- **Согласовано:** в режиме «Системная» приложение следует настройке темы Android.

### API-токен
- **Согласовано:** токен отображается скрытым символами.
- **Согласовано:** токен хранится защищённо в Android secure storage.
- **Согласовано:** токен не должен попадать в логи, сообщения об ошибках, открытый интерфейс настроек или обычное незашифрованное хранилище.
- **Согласовано:** после сохранения токена проверка связи автоматически запускается в фоне.
- **Согласовано:** пользователь может сразу уйти из настроек системной кнопкой Android «Назад», не дожидаясь проверки.
- **На будущее:** после успешной проверки внизу экрана появляется сообщение «Связь с МойСклад установлена»; при неуспехе — соответствующее сообщение, подробная ошибка попадает в Журнал склада.
- **Согласовано:** все проверки выполняются в фоне и не блокируют интерфейс.
- **Согласовано:** токен необязателен для запуска офлайн-версии; приложение без токена открывает главное меню.

## 8. Офлайн-режим и границы первого этапа

- **Согласовано:** первая версия должна быть работоспособной без подключения к МойСклад и без API-токена.
- **Согласовано:** бизнес-функции закупки, заказа, перемещения, инвентаризации и прочих действий пока не реализуются; соответствующие разделы — заглушки.
- **На будущее:** бизнес-операции в офлайн-режиме должны сохраняться локально и отправляться при восстановлении связи.
- **Согласовано:** локальное сохранение и последующая отправка бизнес-операций не входят в текущий этап, так как сами бизнес-функции ещё не созданы.

### Поведение кнопки «Назад» и выход
- На главном экране первое нажатие системной кнопки «Назад» показывает небольшое окно подтверждения с кнопками «Выйти» и «Отмена».
- Повторное нажатие системной кнопки «Назад» в течение 2 секунд после первого нажатия закрывает приложение.

### Уточнение поведения выхода
- Нажатие «Отмена» в окне подтверждения выхода оставляет приложение на главном экране.

### Процесс согласования требований стартовой версии
- Вместо одиночных вопросов согласование проводится пакетами по 10 вопросов в формате теста.
- Для каждого вопроса предлагаются 2–3 или более подходящих вариантов ответа и возможность указать собственный вариант.
- Пользователь отмечает ответы на пакет; после получения ответов все соответствующие изменения требований фиксируются одним обновлением документа и одним коммитом.
- Цикл повторяется, пока требования стартовой версии не будут согласованы.

## Согласование стартовой версии — пакет № 1

1. Верх главного экрана: только календарь и индикатор связи; название приложения в верхней части не добавлять.
2. Неделя на главном экране: семь компактных ячеек в одну строку.
3. Выбранная дата: выделять одновременно фоном ячейки и цветом текста.
4. Полный календарь: открывать нажатием на стрелочку вниз, расположенную под календарём.
5. Список операций под полным календарём: пока не реализовывать содержимое операций; при пустом списке показывать «Нет операций за этот день».
6. Кнопки главного меню: располагать вертикально с небольшими отступами от краёв экрана.
7. Обычные Snackbar-сообщения: показывать до 5 секунд; закрывать раньше, если пользователь нажмёт в любое место экрана.
8. Экран настроек: отдельные блоки с заголовками и настройками внутри.
9. API-токен: разрешить удаление; для замены пользователь сначала удаляет старый токен, затем вводит новый.
10. Иконка приложения: временная простая иконка с названием Lerua Zakup.

Все десять пунктов пакета № 1 согласованы.

## Согласование стартовой версии — пакет № 2

1. Кнопки главного меню: светлый фон и тонкая серая рамка.
